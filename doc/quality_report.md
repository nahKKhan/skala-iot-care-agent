# 구현·품질 검증 정리 (과거 평가 기록)

이 문서는 2026-10-21 11시대의 실제 Ollama 평가와 당시 자동 테스트 기록을 보존한 자료입니다. 현재 제출용 자동 검증 결과와 실행 화면은 [최신 검증 기록](submission_validation.md)과 [README](../README.md)를 참고하세요. 아래 모델 평가 수치를 현재 OpenAI 품질 검증으로 재사용하지 않습니다.

## 구현한 범위

- IoT 매뉴얼 10종·30문단. 상태에 맞는 문서를 BM25로 검색하고 본문·문단 ID·문서 공통 후보 메타데이터를 생성에 사용한다.
- 원인 후보는 검색 문서의 목록에서 선택하고 가능성·추가 확인 항목·출처를 표시한다.
- 후보·출처·허용 조치 문구·확인 한계를 JSON Schema에서 제한하고, 코드로 다시 검수한다. 미달 시 재작성 최대 1회, 재차 미달 시 규칙 안내로 대체한다.
- 정상 절전, 가상 복구 성공, 명령 접수 후 미복구, 재조회 실패·확인 불가를 구분한다.
- SQLite에 점검·조치 전후 관측·결과·검색 근거를 남기고 다음 점검과 화면에서 조회한다.
- 중복 request_id와 초기화 전 버전을 포함한 오래된 요청의 재실행을 방지한다.

## 자동 테스트

- Python 29개 통과: 상태 경계값·비정상 데이터·검색·후보·출처·실제 실패 문구 검수, 정상 절전, 복구 결과 구분, 영속 이력, 중복 요청·오래된 요청, SSE·프록시.
- Node 화면 동작 8개 통과: 중복 클릭·통신 실패·결과 구분·이전 버튼 무효화·검색 근거·유지보수 이력·초기화.
- 합계 37개. 모델 응답을 대역으로 사용하는 자동 테스트이며 실제 모델 답변 품질과 구분한다.
- 브라우저 네이티브 자동화 연결 실패로 이번 변경 화면의 실제 렌더링 수동 확인은 완료하지 못했다. 화면 스크립트 상태와 API 연결 계약은 위 자동 테스트로 확인했다.
- 최종 Python 테스트 중 MCP SDK의 프로세스 종료 권한 경고가 한 번 있었고, 전체 테스트는 종료 코드 0·OK로 완료됐다.

## 고정 사례 평가

- 사례 12개 중 상태 분류 정답이 있는 10개: 이전 규칙 8/10 → 절전 구분 포함 10/10.
- 평가에서 요구한 문서 포함 수: 고정 파일 조회 4/12 → 문단 검색 12/12.
- 최종 실제 Ollama 호출 대상 10개: 출처·허용 조치 검수 10/10 통과, 재작성 없이 응답. 나머지 2개는 없는 장치·대상 누락으로 모델을 호출하지 않음.
- 채팅 중 명령 미실행 12/12. 실제 명령은 사용자의 복구 버튼/API 요청으로만 처리한다.
- 실제 모델: `qwen3.5:2b`, 파이프라인 코드 버전 `ea3b8d95c99e`.
- 실제 모델 호출 사례의 전체 처리 시간: 23.95~56.78초, 평균 38.99초. 같은 기기에서 자동 테스트도 실행한 기록으로, 독립된 성능 벤치마크는 아니다.

이 수치는 개발용 가상 사례에 대한 결과다. 현장 정확도, 독립 검증 세트의 정확도 또는 의미 정확도 100%를 뜻하지 않는다. 기준선 LLM의 답변은 생성·비교하지 않았다.

## 실제 답변 검토에서 남은 문제

출처·형식·조치 검수 통과와 문장 내용의 정확성을 분리해서 봐야 한다.

- Q04·Q05: 배터리 부족과 연결 끊김의 동시 관측을 원인·결과로 연결한 표현이 남았다. 이 데이터만으로 인과관계를 확정할 수 없다.
- Q03·Q08·Q09: 마지막 수신 경과 시간만으로 실제 전송 속도 저하나 추세를 표현하는 부분은 보완이 필요하다.
- 일부 원인 후보가 의미상 유사하다. 후보를 선택했다고 원인이 증명되거나 독립된 여러 원인이 발견된 것은 아니다.
- 위 내용은 Codex의 보조 검토다. 독립된 사람 평가와 미검토 데이터 검증은 남아 있다. JSON의 manual_review를 임의로 합격 처리하지 않았다.

첫 실제 평가에서는 JSON 문자열 조각, 임의 후보 ID, 원인 단정, 절전과 일반 정상 문서 혼재가 발견됐다.
그 사례를 보존하고 회귀 테스트·허용 ID/조치/확인 한계 제약·절전 검색 필터를 추가한 뒤 동일 질문으로 재평가했다.
검수 규칙도 바뀌었으므로 첫 평가의 검수 통과율과 최종 통과율만으로 의미 품질 개선률을 계산하지 않는다.

## 재시작 후 직접 확인할 순서

1. 기존 8100 백엔드와 8600 화면 서버를 각각 Ctrl+C로 종료한다. Ollama는 켜둔다.
2. `bash sh/run_iot_agent.sh ollama`와 별도 터미널의 `.venv/bin/python web_demo_server.py`로 재시작한다.
3. 브라우저를 새로고침하고 sensor-02의 검색 근거·원인 후보·복구 성공을 확인한다.
4. sensor-05의 미복구, sensor-06의 확인 불가, sensor-04의 정상 절전을 확인한다.
5. 유지보수 이력에 각각 다른 결과가 남고, 초기화 후 과거 버튼이 재사용되지 않는지 확인한다.
