# 답변 품질 보완과 실제 모델 재검증

## 수정 내용

1. **동시 관측과 인과관계 구분**: 배터리 부족·연결 불가가 함께 관측된 상태의 설명을 코드 문장으로 제한했다.
   일반 설명의 일부 인과 연결 표현도 검수에서 거부한다. 원인 후보는 미확정 후보 목록에서 선택한다.
2. **정상 보고 대기와 절전 확인 구분**: 보고 대기 조건 안의 설명에 실제 절전 미확인 문장을 고정한다.
3. **조치 순서 검사**: 재시작 안내가 있으면 상태 재조회 안내가 앞에 있어야 한다. 중복 안내도 거부한다.
   두 번 검수 미달 시 규칙 안내에서도 재조회 → 가상 수집기 재시작 순서를 유지한다.
4. **복합 판단 의도 분기**: 확정·단정·배제·전원 문제 질문은 단순 잔량 조회보다 진단을 우선한다.
   전원 문제 배제 요청에는 잔량만으로 배제할 수 없고 전압·접점 추가 확인이 필요하다는 한계를 코드로 표시한다.

critical 상태2종(낮은 잔량+연결 불가, 정상 보고 대기)에는 required_explanation을 프롬프트·JSON Schema enum·코드 검수에 동일하게 적용한다.
이를 통해 관측 한계를 보존하며, 이 부분을 모델의 자유로운 추론 개선이나 추가 학습 효과로 설명하지 않는다.
질문 이름·센서ID·평가 사례 번호에 종속된 규칙을 사용하지 않는다.

원인 후보 선택·일반 관측 설명·허용 조치 선택은 계속 LLM 경로에서 수행한다.
명령 실행은 기존 사용자 버튼·실행 조건·중복 방지·복구 검증을 유지한다.

## 검증 방법

- 고정 질문·공식 문서 색인·가상 장치 데이터는 보완 전과 동일하다.
- 보완 전 코드: ebb0daffb7d1, 보완 후: 90c9dc662a64.
- 질문 버전: 48390bbc9c0f, 문서 색인: 88f03f8b6989, 장치 데이터: b5334ce0e90a.
- 모델은 양쪽 모두 OpenAI gpt-4o 설정이다. 별도 스냅샷 모델 ID는 기록하지 않는다.
- 보완 후 실행: 2026-10-22T09:23:49+09:00 ~ 2026-10-22T09:24:06+09:00.
- 각 질문을1회 평가하며, 실패 시 최대1회 재작성하는 제품 정책을 동일하게 적용했다.
- 임시 DB·독립 MCP, 고정 순서, 앞선 점검 이력을 후속 질문에 포함한다. 기존 시연 DB는 보존한다.
- 보완 전 JSON의 SHA256은 그대로 유지됐다. 기존 실패 답변을 덮어쓰지 않았다.

## 남는 한계

검수의 인과 표현 패턴은 모든 의미 오류를 잡는 완전한 언어 판별기가 아니다.
보고 대기 상태 외의 새 증상·표현, 혼합 의도 질문, 문단 단위 근거의 세밀한 일치는 추가 검증이 필요하다.
후보 메타데이터는 문서 공통 내용이다. 문단 ID가 존재한다는 사실만으로 모든 후보가 해당 문장에 직접 서술돼 있다는 뜻은 아니다.
이번 질문은 개발 과정에서 사용한 소규모 고정 사례이며 독립된 검증 세트가 아니다.
추가 수정 시 새 파일로 반복 평가하고, 사용자·현장 전문가의 표본 검토를 더하는 것이 후속 작업이다.
