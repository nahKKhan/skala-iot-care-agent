# 5분 발표·시연 순서

1. **문제·목적 (40초)**: 이상 알림 뒤에 담당자가 해야 하는 매뉴얼 확인·원인 후보 검토·원격 조치·결과 기록을 연결한다.
2. **구조 (40초)**: 상태 판단과 명령 허용·복구 검증은 코드, 설명·후보 선택은 LLM, 근거는 검색 매뉴얼과 저장 이력이다.
3. **RAG와 성공 시연 (60초)**: sensor-02 점검 → 검색 근거 펼치기 → 후보와 추가 점검 확인 → 가상 복구 → 새 수신 번호 확인.
4. **실패 구분 시연 (60초)**: sensor-05 점검·복구 → 명령 접수지만 미복구·현장 점검. sensor-06은 조회 실패·확인 불가. 이력 패널에서 결과 차이 확인.
5. **정상 절전 (30초)**: sensor-04는 연결이 없어도 예정된 절전으로 처리하고 재시작 버튼이 나타나지 않음.
6. **평가·한계 (70초)**: 자동 테스트와 실제 모델 평가 결과를 구분한다. 소규모 가상 사례임을 밝히고 실패 사례·속도·추가 검증 필요를 제시한다.

시연 전 각 장치를 `가상 상태 초기화`로 준비한다. 초기화 후 다시 점검해야 하며 과거 진단의 버튼으로 실행하지 않는다. 이력은 삭제되지 않는다.

발표 자료에 테스트가 없던 성능 수치나 독립 검증·실제 기기 운용 성과를 추가하지 않는다. 모델이 시간 초과되면 검색 근거와 코드의 안전한 대체 동작을 그대로 설명한다.
