# IoT 수동 회귀 점검

백엔드·화면을 실행한 뒤 아래 입력을 확인한다. 복구 사례는 먼저 해당 장치의 가상 상태를 초기화한다. 이 표는 점검 기준이며 실행 결과를 주장하는 자료가 아니다.

| 입력·동작 | 기대 결과 |
|---|---|
| `sensor-02가 뭐더라?` | 등록 장치 소개, 복구 명령 없음 |
| `sensor-02 배터리 얼마나 남았어?` | 관측 잔량 조회 |
| `sensor-03 로그 보여줘` | 가상 수집 버퍼의 배터리·연결 로그 |
| `sensor-03 로그로 원인을 분석해줘` | 상태·로그·매뉴얼 근거와 원인 후보, 복구 버튼 없음 |
| `sensor-01 점검해줘` | 정상 안내, 복구 버튼 없음 |
| `sensor-02 점검해줘` → 복구 버튼 | 새 데이터 수신, 복구 확인, 전후 값·이력 반영 |
| `sensor-04 점검해줘` | 정상 절전, 재시작 제안 없음 |
| `sensor-05 점검해줘` → 복구 버튼 | 명령 접수 후 미복구, 현장 점검 필요 기록 |
| `sensor-06 점검해줘` → 복구 버튼 | 명령 접수 후 확인 불가, 성공으로 표시하지 않음 |
| `sensor-99 점검해줘` | 미등록 장치 안내 |
| `점검해줘` 또는 두 장치 동시 요청 | 장치 ID 하나를 요청 |
| `sensor-02 점검 기록 보여줘` | SQLite에 저장된 유지보수 이력 |
| `정상 절전과 수신 지연은 어떻게 달라?` | 일반 매뉴얼 검색, 특정 장치 진단으로 표시하지 않음 |
| 복구 버튼 연속 클릭 | 한 번만 요청 |
| 초기화 후 이전 복구 버튼 클릭 | 오래된 제안 실행 금지, 재점검 안내 |
| 모델 연결 실패·잘못된 출력 | 오류·대체 안내와 조회 근거, 자동 복구 없음 |

실제 모델 답변 끝의 `설명 모델`과 대체 안내 여부를 확인한다. 화면 상단 모델명은 설정 정보이며 생성 성공의 증거가 아니다.
