# 1. 신규 AI 서비스 개발 관련안내
## 제공 프로젝트 구성

* web_chat.html : Vue 기반 웹 채팅 UI
* server.py : FastAPI 백엔드 및 API 처리
* agent/graph.py : LangGraph 기반 AI Agent 처리 흐름
* agent/openai_llm.py : OpenAI 모델 연동
* agent/ollama_llm.py : Ollama 모델 연동
* agent/fake_llm.py : 테스트용 Fake LLM
* agent/session_store.py : SQLite 기반 대화 기록 관리
* mcp_server.py : MCP 도구 및 데이터 제공
* agent/mcp_client.py : MCP 서버 연동
* data/ : 기존 장애 진단용 샘플 데이터


## 기존 ZIP 프로젝트 활용 가이드
### ① 웹 화면 변경

* web_chat.html
* 선택한 서비스에 맞게 화면 제목, 입력 항목, 결과 표시 방식 변경
* 필요한 경우 새로운 UI 기능 추가

### ② AI Agent 처리 흐름 변경

* agent/graph.py
* 기존 장애 진단 중심의 요청 분류 및 처리 로직 분석
* 새로운 서비스 목적에 맞게 노드와 처리 흐름 재구성
* 불필요한 기존 장애 진단 로직 제거 또는 대체

### ③ AI 모델 및 프롬프트 변경

* agent/openai_llm.py
* agent/ollama_llm.py
* agent/fake_llm.py
* 신규 서비스 목적에 맞게 프롬프트와 응답 생성 로직 변경
* 기존 장애 진단에 특화된 분류·계획·응답 로직 수정

### ④ MCP 및 데이터 변경

* mcp_server.py
* agent/mcp_client.py
* data/
* 기존 모니터링·장애 대응 데이터를 신규 서비스용 데이터로 교체
* 서비스에 필요한 MCP Tool, Resource, Prompt 구현 또는 변경
* 필요하지 않은 MCP 기능은 제거 가능

### ⑤ API 및 데이터 관리

* server.py
* agent/session_store.py
* 신규 서비스에 필요한 API 추가 또는 수정
* 필요에 따라 사용자별 대화 기록, 작업 결과 저장 기능 구현

※ 모든 파일을 반드시 수정할 필요는 없습니다. 기존 구조 중 활용 가능한 기능은 유지하고, 서비스 목적에 맞는 부분을 변경하면 됩니다.

## 기본 개발 진행 순서
STEP 1. 기존 프로젝트 실행

* 제공된 ZIP 압축 해제
* Mac 환경에서 가상환경 및 패키지 설치
* bash run.sh 실행
* 기존 AI Agent 동작 및 처리 흐름 확인

STEP 2. 신규 서비스 주제 선정

* 서비스명 및 목적 정의
* 주요 기능 선정
* 기존 프로젝트에서 재사용할 기능과 변경할 기능 구분

STEP 3. 서비스 기능 구현

* 새로운 서비스에 맞게 UI 변경
* LangGraph 처리 흐름 및 프롬프트 수정
* 필요한 데이터와 MCP 기능 구성
* 백엔드와 AI 기능 연동

STEP 4. 기능 테스트

* 웹 화면에서 사용자 입력 테스트
* AI Agent의 처리 흐름 확인
* MCP 및 외부 데이터 연동 확인
* 최종 응답의 정확성 및 적절성 검증
* 예외 상황 및 오류 처리 확인

STEP 5. 결과 정리

* 프로젝트 개요 및 주요 기능
* 기존 프로젝트에서 재사용한 구성
* 신규 개발 또는 변경한 기능
* 전체 시스템 구성 및 처리 흐름
* 실제 실행 화면 및 테스트 결과

구현 예시 — AI 학습 도우미로 변경하는 경우
기존 프로젝트의 다음 처리 흐름을 변경할 수 있습니다.
기존 AI Agent
사용자 장애 문의 → 장애 유형 분류 → 모니터링 조회 → 장애 대응 매뉴얼 검색 → 원인 분석 → 최종 답변
신규 AI 서비스
사용자 학습 질문 → 질문 유형 분류 → 학습 자료 검색 → 관련 내용 분석 → 학습 수준에 맞는 답변 생성 → 최종 결과 제공
기존 LangGraph, MCP, LLM, Vue, FastAPI 구조를 활용하면서 새로운 서비스에 필요한 로직과 데이터를 구현하는 방식입니다.
